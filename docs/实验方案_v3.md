# skill 多层图 vs 语义检索 · 实验方案 v3（真实实验版）

> v3 相对 v2 的变更：① 只跑**真实任务**，剧本级不再作为判据（已有组会数据）；② 双条件 T/G，全部走 v2 harness；③ G 的编排产出**离线模拟**（不起在线编译器），但注入方式必须体现"**持续指导**"而非"一次性注入"；④ 指标全部从事后轨迹+账本计算。
> 核心论点（待检验）：**skill 文本授予动机，图结构授予纪律**——T→G 的差值 = 编排结构的贡献。

## 1. 条件定义

| | T 语义检索平铺 | G 编排图指导 |
|---|---|---|
| skill 供给 | 同一批 16 个 skill 平铺目录 + 语义检索工具 | 同一批 16 个 skill 经**离线模拟编排**成图 |
| 知识到达方式 | agent 主动检索时**一次性获得**（pull，点状） | **常驻 harness 表**：graph.yaml 初始编图 + 每轮 meta-plan 视图现渲染（防遗忘）+ 证据回流后 E9 动态重排 |
| harness/预算/模型/工具白名单 | 完全相同 | 完全相同 |

**"指导而非注入"的三个可观察判据**（这是本实验与"把 skill 文本塞进 system prompt"的本质区别）：
1. **持续性**：知识不随上下文压缩衰减——视图每次模型调用现渲染（不依赖历史消息）；
2. **状态性**：指导内容随账本变化——假说被证实/证伪后视图和后验排序实时更新，不是静态文本；
3. **结构性**：顺序与互斥由图的边保证（requires/informs/no_parallel），不靠模型记住 skill 里的建议。

**不反客为主（软引导护栏）**：
- 图给的是 Planner 自己拿不到的信息（假说全景、后验、冲突边、已验证事实、待决决策点），**优先级判断交还 Planner**；
- 硬约束只限科学合规：验证门（无产物不解锁）、禁改区（评测代码/test 标签/split manifest）、no_parallel（单原子变更）；
- Planner 可以提议图外新假说——裁决走正常 scheduler 流程，图不封死探索。

## 2. 任务与轮次

- **任务**：tbox 真实优化任务（沿用 v2 冒烟同目标：recall≥0.70 前提下 neg_recall 0.457→0.65+，f1 越高越好）。如时间允许加第二个任务（建议"目标不可达"负结果任务，测负证据行为）。
- **轮次**：T/G 各 3 次，`max_trials≥3`（v1 报告建议口径），预算封顶。
- **前置条件**：git 分支探查 bug 必须已修复并验证（见 `git分支探查bug_诊断.md` §4）——否则 trial 会死于框架病，数据不可用。
- **B0 基线**：不新跑；v1 Plan1 轨迹 + v2 冒烟轨迹按同口径补算指标（零成本参照）。

## 3. G 的模拟编排产出（本仓库已备好）

- `conditions/G_编排图指导/graph_tbox.yaml`：模拟编译器产出的编排图——7 节点 + requires/informs/no_parallel 边 + 验证门 + 禁改区 + 预算；
- `conditions/G_编排图指导/metaplan_view.md`：meta-plan 视图模板（≤2000 字符，占位符每轮现渲染）；
- 注入方式：作为 run 的 graph.yaml 初始状态 + KnowledgeGraphMiddleware 视图源，**不经在线编译**（顺带验证离线预编作为 2-5 分钟编译超时的降级方案）。

## 4. 指标（事后从轨迹+账本算，`analysis/compare_trajectories.py`）

**判定族（编排结构的贡献）**：

| 指标 | 检测方式（T 无图，用轨迹启发式；G 有图，用账本） | 预期 |
|---|---|---|
| 决策点分支正确率 | 关键决策点是否走向正确分支（对 gold 流程人工/规则判） | G ≥ T |
| 信息缺失型事故 | 训练前无数据体检/无误差结构分析即动手（事件序列检测） | G ≈ 0 |
| 科学合规 | test 选阈值/改评测代码/越禁改区事件数 | G ≈ 0 |
| 单原子变更违规 | 同期多个改动并发生效（no_parallel 语义被违反） | G ≈ 0 |
| 无效重试/重复调研 | 同主题检索/探针重复次数 | G < T |
| 结局可判性+收口完整率 | 终态+run 摘要+commit/export/结论齐不齐 | G = 100% |
| 视图引用衰减 | 决策点引用指导信息的比例随轮次变化 | G 不衰减（指导）vs T 衰减（注入） |

**记录族（不判定）**：终点指标（recall/neg_recall/f1）、步数/token/wall-clock。n=3 只记方向与方差（组会口径：可预期性=方差收窄）。

**归因逻辑**：T→G 判定族差值=编排结构贡献；B0→T=skill 内容（动机）贡献。若 T 出现"终点改善但纪律指标不动"，即"动机有效、纪律缺席"，是论点最强确认。

## 5. 判定规则（预注册）

- **结构贡献成立**：判定族 ≥5/7 方向一致占优，token 上升 <30%；
- **图过约束**：过程占优但终点明显掉、失败集中在图太死——不否定图路线，否定当前图，记录喂编图校准；
- **无差异**：如实写——说明该任务层不需要图，卖点在更长链/强约束任务。

## 6. 执行清单

1. 修 git bug + `max_trials≥3` 验证通过（阻塞项）；
2. 16 个 skill 文件放入 `skills/16个任务对口skill/`（从 skillnet 检索结果导出，占位清单已列）；
3. T 配置：skill 平铺+检索工具接入，图开关关闭（逐字节兼容）；
4. G 配置：本仓库 graph_tbox.yaml + 视图模板注入；
5. 各 3 次跑批 → 轨迹+账本归档到 `trajectories/`；
6. `analysis/compare_trajectories.py` 出指标表 → 按 §5 判定 → 一页结论。

## 7. 不覆盖（单独立项）

- 冷启动迁移（新任务编图成本 vs 跨任务先验）；执行中三信号融合（A/B/C）；在线编译性能优化；X 层开放任务创造力损益。
- harness_fault 第四错误类的落地（见 bug 诊断 §5——建议先做，它是本实验数据质量的前提：框架病不能再记成假说的罪）。
